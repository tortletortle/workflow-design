# workflow_template · 协议手册

> JSON 消息协议:信封(拼接接口)+ 消息(OpenAI 兼容)+ 工具定义 + 翻译产物 + 分发结果 + 运行留痕。
> 全部模型 `extra="allow"`,业务可挂任意 `x-` 前缀自定义字段,拼接/翻译/分发全程透传不丢弃。
> 可 Ctrl+F 搜索任意字段名。

---

## 1. 请求信封(WorkflowEnvelope)

一次 run 的完整描述。可复制的完整示例见 `templates/workflow_request.json`。

| 层级 | 关键字段 | 说明 |
|---|---|---|
| `workflow` | name, version, run_id, step(当前步,引擎递增), max_steps | 运行元数据 |
| `request` | model / capability(二选一,兼容 model_gateway), messages(拼接产物), tools(工具列表), tool_choice, temperature, max_tokens, response_format, stream | OpenAI 兼容请求体 |
| `context` | user_id, session, **vars**(system 模板 `{{var}}` 插值变量), **retrieved**(RAG 注入片段) | 业务上下文注入区 |
| `inputs` | **system_prompt**(模板,支持 `{{var}}`), **history**(Message[]), **user_input** | 拼接器原始素材 |
| `hooks` | 事件名列表 | 生命周期钩子声明(引擎按事件回调,见 §5) |
| `x-*` | 任意 | 扩展字段,全层级透传 |

```json
{
  "workflow": {"name": "客服问答", "version": "1.0", "run_id": "uuid", "step": 0, "max_steps": 8},
  "request": {"model": "mock-smart", "messages": [], "tools": [], "tool_choice": "auto"},
  "context": {"user_id": "u-1", "vars": {"user_name": "张三"}, "retrieved": []},
  "inputs": {"system_prompt": "你好 {{user_name}}", "history": [], "user_input": "帮我查订单"},
  "hooks": ["on_start", "pre_dispatch"],
  "x-department": "support"
}
```

## 2. 消息(Message)

OpenAI 兼容,统一 `role` 字段。extra="allow"。

| role | 必选字段 | 条件字段 | 说明 |
|---|---|---|---|
| system | content | — | 拼接器生成:模板插值 + RAG 注入 |
| user | content | — | 业务输入 / 历史记录 |
| assistant | content | **tool_calls**(模型要调工具时) | content 可为 null |
| tool | content | **tool_call_id**, **name** | 分发器回填的执行结果 |

tool_calls 条目结构(assistant 消息内):
```json
{"id": "call_abc", "type": "function",
 "function": {"name": "query_order", "arguments": "{\"order_id\":\"A-1234\"}"}}
```

---

## 3. 工具定义(ToolDefinition)

OpenAI function 格式。MCP 工具的 `inputSchema` 直接映射到 `parameters`。

```json
{"type": "function",
 "function": {"name": "query_order", "description": "按订单号查询",
  "parameters": {"type": "object", "properties": {"order_id": {"type": "string"}}, "required": ["order_id"]}}}
```

本地工具用 `@tool` 装饰器注册,定义由函数签名+docstring 自动生成。
MCP 工具公开名加 `mcp__{server}__{tool}` 前缀,避免跨服务重名冲突。

## 4. 翻译产物(TranslatedReply)与分发结果(ToolResult)

### 4.1 TranslatedReply

翻译器输出,引擎据此决策。

type | next_action | 说明
---|---|---
text | final_answer | 纯文本回复,run 结束
tool_calls | dispatch_tools | 模型要调工具,进入分发
empty | final_answer | 空回复(防御),按终答处理

```json
{"type": "tool_calls", "text": null, "finish_reason": "tool_calls",
 "tool_calls": [{"id": "c1", "name": "mcp__kb__search", "arguments": {"query": "退货"},
                 "source": "mcp:kb"}],
 "next_action": "dispatch_tools"}
```

### 4.2 ToolResult

分发器输出。单条失败不中断整体 run(ok=False 回填错误文本给模型自纠)。

```json
{"tool_call_id": "c1", "name": "mcp__kb__search", "ok": true,
 "content": "关于 退货 的检索片段", "source": "mcp:kb", "latency_ms": 12}
```

## 5. 生命周期钩子(hooks)

信封 `hooks` 字段声明要触发的事件;引擎在对应节点调用 HookRegistry.fire()。
钩子函数签名为各事件的参数列表(见下),返回值被忽略(只做观察/埋点/审计)。

| 事件 | payload | 触发时机 |
|---|---|---|
| on_start | envelope | run 开始 |
| pre_model_call | envelope, request | 请求发出前 |
| post_model_call | envelope, response | 收到模型回复后 |
| pre_dispatch | envelope, tool_calls | 分发工具前 |
| post_dispatch | envelope, tool_results | 工具执行完成后 |
| on_finish | envelope, result, reason | run 结束(final/max_steps) |
| on_error | envelope, error | 任意异常 |

---

## 6. 运行留痕(RunResult)

status | 含义
---|---
final | 模型返回终答
max_steps | 超过 max_steps 上限(可观测,不静默)
error | 引擎异常(含错误描述)

`steps[]`:每轮循环留痕(step, request_messages, reply_type, tool_calls, tool_results, final_text)。
`transcript[]`:完整对话记录(system/user/assistant/tool),可用于调试和上下文传递。

## 8. 权限审核(PermissionPolicy)

两层审核,在分发器执行前统一拦截;拒绝不抛异常,错误文本作为 tool 消息回填给模型,可改用低危命令重试。

**工具级(创建时声明)**:`@tool(permission="shell")`;MCP 服务在 mcp_servers.json 条目加 `"permission"` 字段(默认 `mcp`)。未声明视为 `default`。

**命令级(种类限制)**:参数含 `command` / `program` 的工具(终端/命令/PowerShell)自动审核:

| 类别 | 危险等级 | 示例 |
|---|---|---|
| read | 0(最低) | echo, dir, Get-*, git status/diff, Write-Output |
| write | 1 | New-Item, Set-Content, git add/commit, npm install |
| execute | 2 | python, node, bash, git push, Start-Process |
| destructive | 3(最高) | rm/del, Remove-Item, Stop-Process, format, taskkill |

规则:多段命令(管道 `|`、`;`、`&&`)取**最高危段**;`>` 重定向至少 write 档;`cmd /c X`、`powershell -Command X` 对内部命令递归分类;未知命令按 execute 档保守处理;允许高档自动涵盖低档。规则表可用 `register_rule("git mv", "write")` 扩展。

```python
from app.permissions import PermissionPolicy

policy = PermissionPolicy(
    allowed_permissions={"default", "shell"},  # 本次 run 授予的工具权限
    allowed_categories={"read", "write"},      # 允许到 write 档(含 read)
    allow_unknown=False,                        # 未知命令是否放行(默认拒)
    blocked_tools={"powershell"},               # 直接拉黑个别工具
)
engine = AgentEngine(model, registry, policy=policy)
```

不传 policy = 不审核(向后兼容);MCP 条目示例:`{"name": "filesystem", "permission": "fs", ...}`,策略需含 `"fs"` 才放行。

## 9. 长期记忆(已启用:官方 MCP memory)

- 服务:`@modelcontextprotocol/server-memory`(知识图谱:实体/关系/观察),stdio 子进程
- 持久化:`MEMORY_FILE_PATH` 指向 JSONL 文件(当前配置:`workflow_template/memory_store.jsonl`),跨进程、跨会话、重启不丢
- 工具(模型可调用):`mcp__memory__create_entities / create_relations / add_observations / search_nodes / read_graph / open_nodes / delete_*`
- 权限:条目声明 `permission: "memory"`,策略需 `allowed_permissions` 含 `"memory"` 才放行
- 接入方式:`registry.attach_mcp_config(json.load(mcp_servers.json))` 自动挂载 enabled 服务
- 验证 demo:`uv run python -m app.main --memory`——会话 A 写入事实 → 彻底关闭子进程 → 会话 B 全新信封检索成功

短期记忆 = 引擎 transcript(单次 run 内多轮累积,`inputs.history` 可跨 run 手动带入);长期记忆 = 本节 MCP memory。
