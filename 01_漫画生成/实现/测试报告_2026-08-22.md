## 🐛 发现的问题

### 1. 方法签名不匹配 (严重)

**问题描述**:  
`ImageClient` 类的 `_via_images_api()` 和 `_via_chat_api()` 方法缺少 `model` 参数，导致调用时参数数量不匹配。

**影响范围**:
- 所有图像生成功能
- 导致 8 个测试失败

**错误信息**:
```
TypeError: ImageClient._via_images_api() takes 3 positional arguments but 4 were given
```

**根本原因**:
- `generate()` 方法接受 `model` 参数并传递给内部方法
- 但 `_via_images_api(self, prompt, size)` 定义中缺少 `model` 参数
- `_via_chat_api(self, prompt, size)` 同样缺少 `model` 参数

**修复方案**:
在 `app/client.py` 中：
```python
# 修复前
async def _via_images_api(self, prompt: str, size: str) -> bytes:

# 修复后
async def _via_images_api(self, prompt: str, size: str, model: str | None = None) -> bytes:
```

### 2. HTTP 429 错误处理不当 (重要)

**问题描述**:  
遇到 HTTP 429 (配额耗尽) 时，代码抛出 `RuntimeError` 而不是 `QuotaExhaustedError`，并且错误地尝试降级到 chat 通道。

**影响范围**:
- 配额管理功能
- 熔断机制
- 导致 2 个测试失败

**问题分析**:
1. 配额耗尽是账号级别的问题，降级到 chat 通道无意义
2. 应该立即抛出 `QuotaExhaustedError` 让上层熔断
3. 避免浪费时间在已知失败的降级请求上

**修复方案**:
```python
# 在 _via_images_api 中
if resp.status_code == 429:
    raise QuotaExhaustedError(f"images HTTP 429: {resp.text[:200]}")

# 在 generate 中
try:
    return await self._via_images_api(prompt, size, model)
except QuotaExhaustedError:
    raise  # 配额错误不降级，直接抛出
except Exception:
    return await self._via_chat_api(prompt, size, model)
```

### 3. 安全问题：硬编码 API 密钥 (严重)

**问题描述**:  
`test_image_api.py` 文件中硬编码了真实的 API 密钥。

**安全风险**:
- API 密钥暴露在代码中
- 可能被版本控制系统记录
- 存在泄露风险

**修复方案**:
- 重写 `test_image_api.py` 使用项目配置系统
- 从 `.env` 文件读取 API 密钥
- 添加安全警告和使用说明
